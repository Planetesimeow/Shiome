# 平台推荐机制深挖 · Fable 5 研究 Prompt

> 用途：把下面【PROMPT 开始】到【PROMPT 结束】之间的全部内容，原样发给 **Fable 5（模型 ID：`claude-fable-5`）**。
> 它会尽力复现抖音 / 小红书 / B站「水面之下」的推流规则，并按要求把一份**可复用的问题清单 + 当前最佳答案**整理成一个 Markdown 文件，供长期反复追问、随平台变化定期重跑。
>
> ⚠️ 重要认知：任何模型都拿不到平台真实算法（黑箱、动态变化、从未完整公开）。这份产出是**最佳复现（reasoning framework），不是真相**。它的价值在于当推理框架用——所以下面的 prompt 强制要求打置信度标签、给可证伪的验证方法。别把里面任何数字当成硬判据。
>
> 建议每隔一段时间、或发现推流规律明显变化时，重跑一次，在产出文件底部追加「更新记录」。

---

════════════════════ 【PROMPT 开始】 ════════════════════

你是一位资深的内容平台推荐系统 / 增长分析专家，长期研究短视频与图文社区平台的分发机制。

## 任务

针对 **抖音、小红书、B站（哔哩哔哩）** 三个平台，尽你所能地复现每个平台「水面之下」的内容分发 / 推流规则与排序逻辑，逐平台**深挖**。产出用于一个个人创作者的数据分析工具做参考框架——不是让你给出确定的算法真相，而是给出一份诚实、结构化、可长期维护的最佳复现。

## 铁律（认知纪律，最重要，违反即失败）

1. **每一条结论都必须打置信度标签**，用下面这套标准：
   - 【实证】平台官方文档 / 公开创作者规则明确写过，或可稳定复现。
   - 【共识】创作者社区广泛观察到、被反复验证的经验。
   - 【推断】基于通用推荐系统 / 机器学习原理的合理推理。
   - 【猜测】缺乏依据的推测，仅供启发。
2. **不许把具体数字当成硬性事实**。如果给出诸如「完播率 45%」「点赞比 3.5%」这类数字，必须标注为「民间经验值 / 量级参考」，并说明它来自什么样本、适用哪类账号与内容——泛娱乐大盘的经验值不能直接套到垂类精准账号上。
3. **每个平台都要单独列出「我不知道 / 无法验证的部分」**（Open Questions）。宁可留白，不要用自信的语气填空。
4. **不要编造引用来源**。是推断就说是推断；是社区共识就说是共识，别包装成官方结论。
5. **每条关键结论尽量附一个「可证伪的预测」**——即一个创作者能自己做实验去验证或推翻的说法（例如「若把视频前 3 秒的钩子前置，24 小时完播率应上升，从而进入下一级流量池」）。

## 每个平台要深挖的维度（这也是要沉淀下来的「问题清单」）

对**每一个平台**，逐条回答以下维度（回答时带上置信度标签）：

1. **流量池分级 / 冷启动**：新内容初始曝光怎么分配？新号 vs 成熟号的差异？各级流量池大致的量级与晋级的触发条件？
2. **核心排序信号与权重排序**：完播率、平均播放时长、点赞、评论、转发、收藏、关注转化、复看、主页访问、进度条拖拽……哪些最重要、大致的优先级顺序、以及这个平台和另外两个平台在权重上的关键差别。
3. **时间动态 / 爬升曲线**：健康爬升曲线 vs 限流曲线 vs 自然衰减曲线，形状上怎么区分？发布后的关键时间窗（1 小时 / 24 小时 / 3 天 / 7 天）分别在发生什么？
4. **账号标签 & 人群定向**：系统如何给账号打垂类标签？发不对口内容导致「标签漂移」的代价是什么？初始人群包怎么选？兴趣扩散 / lookalike 如何工作？
5. **限流 / 降权**：常见触发原因（搬运 / 水印 / 站外导流 / 敏感词 / 低质 / 违规营销等）；创作者如何识别自己「中招」了；限流在数据曲线上的特征；如何恢复 / 申诉。
6. **内容形态影响**：视频时长甜区、封面、标题 / 文案、话题标签、BGM / 热点音的作用。B站请额外覆盖：三连（点赞投币收藏）、分区选择、进度条留存、长视频的完播逻辑。
7. **搜索 vs 推荐**：两条流量来源的权重关系。小红书请重点讲 SEO / 关键词 / 收藏带来的长尾流量；B站请讲搜索与 tag 的作用。
8. **互动质量 vs 数量**：高意向互动（有转化意向的评论、私信、主页访问、收藏、转发）与泛互动（随手点赞）在系统层面和创作者决策层面分别怎么看待。
9. **商业化信号**：广告 / 电商 / 带货内容的处理差异——抖音（DOU+ / 千川）、小红书（报备 / 蒲公英）、B站（花火 / 商单）；未报备商业内容的限流风险。
10. **平台特异性怪癖**：明确标出每个平台「和另外两个反着来」的地方（例如小红书重收藏 + 搜索长尾、B站重三连 + 完播 + 长内容、抖音重完播 + 快速爬升）。
11. **近期变化 / 趋势**：你所知的、这些平台推荐机制近期的调整方向。

## 本项目的特定视角（回答时请始终带着这个视角）

- 目标账号追求的是**「精准触达 > 泛量增长」**。所以请刻意区分：**哪些信号服务于「精准触达目标人群」，哪些只服务于「泛流量放大」**。不要默认把泛量指标当成好指标。
- 请把结论组织成可以直接更新进一段「平台机制参考框架」文本的形态——它会被当作**给模型的推理参考**，而**不是打分及格线**。也就是说，重点是让人 / 模型能识别「一条曲线的形状像哪种模式」，而不是拿数字去卡及格。

## 产出与存档要求

请把成果整理成**一个 Markdown 文件**，建议文件名 `docs/platform-mechanism-findings.md`，结构如下：

1. **文件头**：日期戳 + 「最佳复现，非真相」免责声明 + 置信度标签图例（【实证】/【共识】/【推断】/【猜测】的定义）。
2. **第一部分 · 可复用问题清单（Question Bank）**：把上面「每个平台要深挖的维度」整理成一份干净的、可长期反复追问的问题清单，作为以后定期重跑的研究框架。
3. **第二部分 · 各平台当前最佳答案**：抖音 / 小红书 / B站 三节，每节按上面 11 个维度逐条作答，每条都带置信度标签。多用表格和列表。
4. **第三部分 · 可验证实验清单**：列出创作者能自己做的对照实验（控制变量、怎么发、看什么指标），用来逐步把【推断】【猜测】升级成【共识】【实证】。
5. **第四部分 · 未知 / 待验证问题（Open Questions）**：逐平台列出你不确定或无法验证的点。
6. **第五部分 · 跨平台冲突点**：「为一个平台优化、却会在另一个平台反噬」的做法清单。
7. **文件底部 · 更新记录**：预留一个每次重跑时追加的区块（日期 + 这次哪些结论升级 / 降级了置信度 + 变化原因）。

如果你有写文件的能力，直接把该文件写到 `docs/platform-mechanism-findings.md`；如果没有，就把完整的 Markdown 全文输出出来，方便我复制保存。

开始吧。记住铁律：诚实 > 完整，标注置信度 > 显得确定。

## 复用与维护建议（给人看的，不用发给模型）

- **定期重跑**：平台算法会变。建议每季度、或发现自己账号推流规律明显异常时重跑一次，把新结果追加进 `docs/platform-mechanism-findings.md` 的「更新记录」。
- **回流到代码**：产出成熟后，可把其中【实证】【共识】级别的结论，提炼进 `app/analysis/prompts.py` 的 `PLATFORM_MECHANISM_CONTEXT`，让五个分析模块共享同一套参考框架。注意：进代码的仍然是「形状 / 模式」描述，不是打分及格线。
- **配合快照数据**：这份框架回答「该看什么模式」，但要真正看到模式，还需要 MEMO 里提到的 `video_snapshots` 时间快照数据。两者配合才有意义。
