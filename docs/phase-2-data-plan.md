# Phase 2：可信数据处理与内容复盘

确定于 2026-09-18。承接分支：`release/phase-2-dataprocessing`。目标版本：`1.0.1`。

本文固定开发方向及验收边界，所列新能力均待实现。当前版本仍使用单张截图识别与确认，旧 CSV
导入已移除。本阶段先完成下面的第 1 步，再依次交付；每项独立改动单独开分支和 PR，遵守
[分支与版本约定](workflow.md)。Phase 1 的分支和历史发布记录保留。

## 目标与边界

帮助创作者找到可持续制作的内容方向，改善观看和涨粉。先能回答「数据从哪里来、怎样计算、
哪些作品可比较」，再回答「下一条可以试什么」。保持 iPhone 网页使用、多用户数据隔离和低成本部署。

代码负责表格解析、单位转换、校验、身份关联、去重、统计和数值趋势；AI 负责内容语义、趋势解释、
假设与反馈。截图文字先走可验证的 OCR 与规则，低置信度结果交人工确认；视觉模型是待评估的
按需兜底，其提取结果仍是草稿。不能用 AI 补造缺失值、分母、时间或平台规则。

暂不加入原生 App、商业转化看板、全平台抓取、完整粉丝画像、全量评论/私信或重视频理解。
目标选择器作为后续能力保留；外部平台 API 的接入不阻塞自己的数据处理。

## 1. 先定义数据，而不是先画新的分析图

每项指标必须有：键名、平台原始名称、定义、单位、数据粒度、时间口径、是否可累加、分母要求、
可用来源和版本。保留原始文本、原始单位、精度/舍入状态；缺失、不适用、权限不足和真实零分开。
不同用户、平台账号之间隔离；同名指标只有定义、粒度、周期和单位一致才可比较。

| 数据层 | 身份和时间 | 典型用途 |
|---|---|---|
| 账号日数据 | 用户、平台账号、当地日期、来源时区 | 播放/互动/投稿日序列，粉丝变化 |
| 账号周期数据 | 账号、明确的起止日期、截止时间、统计口径 | 平台 7 日/30 日汇总、同类作者比较 |
| 作品累计观察 | 平台作品 ID 或人工确认的身份、数据截止时间、发布时间及精度 | 发布后相同年龄的表现和快照增量 |
| 作品周期数据 | 作品身份、起止日期、截止时间 | 作品对某周期新增播放的贡献 |

这些是拟定的逻辑模型；第一个实现 PR 再确定兼容旧库的表结构和迁移。不要仅凭标题相似就自动
合并作品。没有平台作品 ID 时由用户确认关联，并保留依据。

观察记录还需保存文件/截图批次、文件哈希、页/行/单元格或截图区域、导入时间、提取方法及版本、
确认状态、修订关系。发布时间、截图时间、页面数据截止时间、上传时间分别记录。
手机在日本不代表平台统计采用日本时区；页面没有说明时标为未知，由用户确认后参与跨日比较。

必须先落实的口径（平台页面定义来自创作者提供的真实导出和指标说明）：

- 账号总播放量是周期内所有作品的播放，包含历史作品及重复观看，排除本人观看；不能等同于
  本期发布作品的累计播放之和，也不能当成独立观众数。
- 完播率、5 秒完播率、2 秒跳出率分别保存。封面点击率的分母是封面曝光量，不能换成播放量。
- 百分比不直接相加或平均。只有已知、同口径的分子和分母才生成合并比率；没有分母时保留平台原值。
  平均播放时长同样需要匹配的观看次数才能加权。
- 互动率先保留平台定义。若另算 `(点赞 + 评论 + 分享) / 播放`，必须标为 Shiome 自定义指标，
  说明是否包含收藏，不冒充平台互动率。
- 总粉丝量是时点存量；净增/吸粉/脱粉是期间变化。回访粉丝是否跨日去重尚待定义，暂不跨日相加。
- 「同类作者」是平台按相似领域或粉丝量级给出的参照，不等同于同 tag、同时长视频的平均表现。
- 「万」等缩写保留舍入精度。低于门槛看不到的画像属于不可用，不能存为零。
- 保留平台流量激励、付费推广等原始标记；没有同口径证据时，不从总播放中自动扣出所谓自然播放。

发生冲突时保留两份证据供复核，不按上传先后静默覆盖；旧截图不能覆盖较新的累计值。
平台修订后累计值可能下降，应形成带原因的修订，不能强行取最大值或将差值当作负播放。

## 2. 标准导入：先覆盖真实的两种导出

`reference/` 已提供的是两份 XLSX，均为账号日数据。它们没有单作品身份，不能直接用于判断
某条内容的完播或涨粉。公开测试仅使用人工合成数据，不提交真实导出或截图。

| 导出 | 原始列 |
|---|---|
| `数据表现_短视频全量指标.xlsx` | 日期、投稿量、总播放量、总点赞量、总分享量、总评论量、5秒完播率、2秒跳出率、封面点击率、平均播放时长 |
| `数据表现_粉丝全量指标.xlsx` | 日期、总粉丝量、粉丝净增、吸粉量、脱粉量、回访粉丝量 |

流程固定为：选择自己的平台账号 → 检测导出类型/模板版本 → 代码解析 → 展示日期、单位、缺失、
重复和冲突预览 → 用户确认 → 事务入库。文件没有账号身份，必须显式绑定；不由 AI 猜账号。

原始 XLSX 通过各自适配器进入统一观察模型；CSV 使用有版本的明确模板，先覆盖上述账号日数据。
模板要标明字段、单位、粒度与时间口径，不恢复旧的模糊表头通吃解析器。未知表头、混合数据粒度、
歧义日期和不支持的模板须提示处理，不能静默吞行。百分号、秒和空值由代码解析；不执行工作簿公式。

相同批次重复上传无新增；改名或日期重叠的文件按观察身份逐项比较。新值不同则生成修订待确认，
保留旧证据。撤销某批次只撤销它的贡献，不删除其他批次或用户后续编辑的数据。

验收：两类合成表和 CSV 模板均可预览/导入；重复、重叠、空值、百分比、异常日期和冲突可复现；
跨用户访问被拒；失败事务不留下部分数据；撤销不影响其他来源。整个流程无模型调用。

## 3. 截图用于补表格没有的数据

以下是目标采集范式。现有[采集指南](capture-guide.md)继续描述当前能用的入口；等分组功能实现，
再把新范式同步到 UI 和操作指南。24 小时/72 小时/7 天只是我们的复查节奏，不是平台推流期限。

| 何时 | 截取什么 | 需要的数据 |
|---|---|---|
| 首次建档或身份变化 | 作品列表，必要时附作品链接 | 标题、发布时间、时长、图文/视频、作品 ID、激励/推广标记 |
| 每周 | 优先导出两份表；截图补账号数据总览及同类作者比较 | 明确周期、平台汇总值、同类百分位、更新时间 |
| 发布约 24 小时 | 单作品数据概览 | 播放、互动、截止时间，建立早期观察 |
| 发布约 72 小时 | 数据概览、吸引力分析、观众分析；推荐补流量来源页 | 完整完播/5秒/2秒、平均观看、吸粉/脱粉、推荐/搜索来源 |
| 发布约 7 天 | 按事先确定的全量或抽样规则重复关键页面 | 较晚观察；保留选样规则，避免只跟踪表现好的作品 |
| 需要解释当周播放贡献 | 周期内的全部作品贡献页，页面提供时采集 | 单作品本周期新增播放；TOP3 只作为局部样本 |

每组只对应一个账号、一条作品、一次观察。页面保留完整指标名、值、单位、标题及时间范围；
续图携带组内关联，不能只依靠截图上传顺序猜身份。不同截止时间/周期不能强制并成一次观察。
长图分段避免重复计数。曲线没有读得出的刻度和值时仅记定性描述，不反推精确序列。

OCR 路线先用代表性页面验证数字、百分号、小数点、时区和单位的识别错误率，以及小服务器的
内存和延迟。初期宁可显示待确认字段，也不把识别置信度当作事实正确的保证；视觉模型不默认常开。

验收：多图补录不生成重复作品/快照；每个值能追到原图区域；跨组冲突与身份歧义必须可见；
新旧截图倒序导入仍能正确保留观察历史。不能确认的值保持缺失。

## 4. 代码统计：每个数都能重算

先做账号日趋势、同周期汇总、作品同口径快照差值和粉丝变化校验，再做内容系列比较。
匹配平台账号、作品形态、时长区间、发布后年龄和推广标记；排除目标作品本身，展示每项指标的
有效样本量、缺失比例和选样规则。无法匹配或样本不足时直接展示限制，不强行给排名。

优先显示中位数、四分位区间及原始散点；如果展示平均值，明确它是作品均值还是按分母加权的
总体比率。新发作品累计量不与旧作品终值直接比较，重叠时间窗不重复汇总。
从「用户提供事实」到「计算结果」都带选数、公式版本和输入记录 ID；数据修订后结果失效重算。

当前改造入口是 `app/main.py` 的身份匹配、upsert 和截图保存，`app/database.py` 的快照模型，
以及 `app/analysis/prompts.py` 的最近作品平均基线。现有日期截断、缺少完整时间口径和缺少分层的
基线需要逐步替换；旧库原始记录先保留，不把历史缺失时间补成虚假的精确时间。

验收：相同输入得相同结果；每项结果可追溯；未知分母不出合并比率；同/异周期与倒序快照有测试；
平台汇总与本地计算不一致时展示范围/修订差异，不擅自调平。

## 5. AI 反馈与内容实验

给 AI 的输入是已确认的事实和代码计算结果、内容标签、目标与相关笔记；带单位、样本量、出处
和缺失说明。数值走势由代码计算，AI 解释可能原因、提出可复查的内容实验，不能把相关性写成因果。
每个结论引用实际参与分析的记录；事实、解释、建议在输出中分开。证据不足时不生成流量池等级、
限流诊断、固定爆量阈值或确定的流量预测。

按输入版本、模型、提示词版本和分析类型缓存；用户按需触发，同一数据不重复付费。
每次实验记录改了什么、要看的指标、比较组与复查时间。未来的目标选择器沿用这套事实层。

验收：重算和浏览无需模型；AI 不能写回数值事实；修订数据使相关缓存失效；输出能定位实际依据；
测试使用模拟响应。邀请用户的数据与分析缓存持续隔离。

## 6. 外部数据：先验证能力，再决定接入

希望比较同类型、同 tag 作品的播放、完播与互动。当前没有实测证据证明任一候选 API 能提供
这些指标的全平台完整统计；样本总量与全平台总量必须区分。

抖音官方的[视频互动数据能力](https://developer.open-douyin.com/capacity-center-page/capacity-detail/7448483112163590181)
面向授权用户自己的视频，页面明确限制平台统计分析用途，不能据此实现全平台参照。
TikHub 的[单作品统计文档](https://docs.tikhub.io/493289600e0)可作为候选：厂商描述了播放及互动字段，
也注明播放可能取不到。这是文档能力，尚未实测；不能据此承诺完播字段、全量覆盖或与后台完全一致。
其[使用条款](https://docs.tikhub.io/9453286m0)限定内部商业使用并限制服务转供，
Shiome 多人服务的使用范围需在接入前明确。

另开验证任务，用小规模、包含不同粉丝量和播放层级的同类作品样本检查：字段实际返回率、与自己
后台的误差、延迟、更新成本、完播/互动分母、推广口径及使用范围。事先定义抽样和去重规则，
不能只选热门视频；多 tag 的同一视频不能重复计数。新近发布作品的累计播放也不等于某周新增播放。
未达到可用标准时保留为研究，不为了接 API 牺牲数据可信度。

机制解释以[抖音官方透明度资料](https://trust.douyin.com/algorithm/)为核验入口；
[已有机制研究](platform-mechanism-findings.md)保留为历史资料。民间固定流量池、权重和阈值只记为
待验证假设，不转成产品评分规则。上述外部页面核对日期：2026-09-18，正式接入时再核验。

## 交付顺序与本阶段完成条件

| 顺序 | 独立交付 | 放行条件 |
|---|---|---|
| 0 | 本文、路线图和 1.x 版本规范 | `1.0.1`（创作者指定），仅文档和版本元数据 |
| 1 | 指标字典、观察/出处模型与迁移 | 明确口径，历史数据与用户隔离可验证 |
| 2 | 标准 XLSX/CSV 导入 | 预览、确认、冲突、幂等、撤销均成立 |
| 3 | 截图分组与复核 | 身份和观察准确关联，OCR 路线经样本验证 |
| 4 | 确定性统计与可比基线 | 同口径可重算，样本与缺失可见 |
| 5 | AI 反馈及实验记录 | 引用事实、按需调用、结果可复查 |
| 6 | 平台 API 可行性结论 | 给出是否接入及其依据，接入本身不作为发布前置条件 |

每行可按迁移、API、界面拆成依赖明确的小 PR，不预先固定每个功能的开发版本号。
`1.0.1` 发布前，自己的表格与必要截图应能形成「导入—确认—计算—解释—复查」闭环，所有
展示的核心指标能追到原始证据。云端部署保持单独的发布步骤，规划 PR 不触发部署或数据迁移。

## English

Phase 2 targets `1.0.1` on `release/phase-2-dataprocessing`; Phase 1 is retained.
Define metric semantics, time scopes and provenance before adding standard XLSX/CSV imports,
grouped screenshot observations, deterministic statistics and evidence-based AI feedback.
Account daily data, period aggregates and post observations are separate. Unknown values and
denominators remain unknown; imports and revisions must be reviewable, reproducible and isolated
per user. External APIs require a separate coverage, accuracy, cost and usage-rights assessment.
This document describes planned work, not capabilities already implemented.
