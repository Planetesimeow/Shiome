# 登录账号、邀请与数据隔离

Shiome 的登录账号代表一个使用者；应用内的“账号”仍代表这个使用者在抖音等平台上的创作者账号。
一个登录账号可以保存多个创作者账号。不同使用者的作品、分析和备份保存在独立数据库中。

## 现有个人实例升级

1. 使用原有登录口令进入，完成一次管理员设置。
2. 若服务器已经配置 Anthropic 密钥，页面会提示已配置，无需重新输入；否则输入一次密钥。
3. 设置自己的用户名和密码。原有数据库继续归这个管理员使用，既有作品、画像、分析和备份保留。
4. 此后用用户名和密码登录。原有的仅口令会话会失效；无需给普通用户分发模型密钥。

部署时同时将已有 `.env.production` 中的 `ANALYSIS_MODEL`、`VISION_MODEL` 改为
`claude-sonnet-5`，并保持 `VISION_PROVIDER=anthropic`。代码更新不会覆盖已有环境变量。

全新实例也先配置部署用初始化口令和稳定的 `SHIOME_SECRET_KEY`，再从网页创建管理员。
初始化接口需要通过原有口令验证，不允许互联网上的访客抢先认领实例。
旧的 `SHIOME_API_TOKEN` 如有配置，是管理员的服务端集成凭据，不用于普通用户登录。

## 邀请与账号设置

管理员打开“工具 → 账号设置”，创建有效期为 7、14 或 30 天的邀请链接，发给指定的人。
每个邀请只能注册一次，可以撤销。注册者自行设置用户名和密码，默认是普通用户。
邀请凭据只在创建时返回，数据库只存其哈希；链接使用 URL 片段，避免凭据进入服务访问日志。

用户可以在账号设置修改用户名和密码。修改密码后，其他设备需要重新登录。
管理员可以停用、重新启用普通账号；停用立即阻止已有会话继续访问，数据保留。

忘记密码时，由服务器维护者运行以下命令并在提示中输入新密码，不把密码写进命令参数：

```bash
docker compose -f compose.yaml -f deploy/compose.small.yaml exec app python -m scripts.reset_user_password <用户名>
```

## 共享密钥与费用

所有受邀用户共用管理员配置的 Anthropic 密钥，费用由管理员承担。
网页新保存的密钥使用 Fernet 加密，密钥材料来自稳定的 `SHIOME_SECRET_KEY`，保存在私有身份库。
密钥保存后不向前端返回；普通用户不能查看或修改。已有环境变量配置仍可沿用。

`ANALYSIS_MODEL` 和 `VISION_MODEL` 默认均为 `claude-sonnet-5`。Sonnet 5 默认开启思考，
当前结构化工具输出请求显式关闭思考，并使用 4096 的输出上限，见
[官方迁移说明](https://platform.claude.com/docs/en/models/sonnet-5/migration-guide)。
当前按每百万 token 输入 2 美元、输出 10 美元记账，依据
[Anthropic 的价格更新](https://www.anthropic.com/news/claude-sonnet-5)。

个人页面仅显示自己的用量；管理员设置页显示全站用量和共享月度预算。
`SHIOME_MONTHLY_BUDGET_USD` 对所有用户合计生效，已有个人账本在管理员初始化时纳入全站账本。
当前单 worker 同时处理一个付费请求，其他请求可以稍后重试；发起调用前会再次检查共享预算。
仍然按已记录费用判断，最后一次调用可能超出剩余额度，不是供应商账单的硬上限。

## 存储与备份

以 `SHIOME_DB_PATH=/data/shiome.db` 为例：

- `/data/shiome.db`：原有个人数据库，归首次管理员。
- `/data/shiome-identity.db`：登录用户、密码哈希、邀请、加密共享密钥和全站用量。
- `/data/shiome-users/<随机内部 ID>/shiome.db`：每位新用户的独立数据库。
- 各数据库旁的备份目录与 `/data/identity-backups`：每日一致性快照，保留最近 10 份。

请求中的用户身份来自已验证的会话，数据文件由服务器查表决定，客户端不能传路径或用户 ID
来选择别人的数据库。异步请求与线程池使用请求上下文，导出报告、截图识别入库和分析也遵守此边界。
现阶段仍为一台服务器、一个 worker；增加副本前需要重新设计存储和任务调度。

网页“下载我的数据备份”只导出当前用户的数据，不含登录用户表、其他用户数据或共享密钥。
管理员在网页中也只下载自己的内容。服务维护者需要额外备份整个身份库和各用户数据库，
并单独保管环境配置中的 `SHIOME_SECRET_KEY`；仅恢复某个人的下载文件不能恢复整个服务。
更换或丢失此密钥会使已有会话失效，也会影响已加密模型密钥的解密。

升级或整站迁移前，停止应用后备份整个持久数据目录，或逐库使用 SQLite backup API 创建一致副本；
不能直接复制正在写入的数据库。恢复时一并恢复身份库与对应用户文件，并检查文件归属和可读权限。
自动异地备份仍需另行配置。服务器维护者拥有磁盘访问权限；这里隔离的是不同应用用户的访问。
